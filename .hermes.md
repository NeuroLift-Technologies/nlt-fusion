## Commit Format

Every commit must follow:

```
[AGENT_NAME] type(scope): description
```

- **AGENT_NAME:** `HERMES`
- **Allowed types:** `feat`, `fix`, `docs`, `refactor`, `chore`, `test`, `ci`
- **Scope:** Short noun phrase for the area affected
- **Description:** Imperative mood, no trailing period

**Examples:**
```
[HERMES] feat(plugin): add NLTGovernanceSubsystem WorldSubsystem base class
[HERMES] fix(build): correct Build.cs include paths for ASFDK-C++ pillars
[HERMES] docs(governance): write handoff record for Phase 7 UE integration
[HERMES] fix(phase7): resolve __isoc23_strtoull linker errors on glibc < 2.38
```

**Template:** `templates/commit-message.md`

## Pull Request Workflow (Non-Negotiable)

- **Always work from a feature branch** — never commit directly to `main`
- **Always open a Pull Request** — never push directly to `main` or protected branches
- **Use the NLT PR template:** `PULL_REQUEST_TEMPLATE/agent-contribution.md`
- **PR description must include:** Agent Contribution Checklist, scope declaration, changes summary, build verification, governance/handoff notes
- **PR reviewers on this repo:** CodeRabbit (automated), Poolside AI, OpenCode, kilo-code-bot, human approvers (JDUB1216)
- **Attribute review comments to the correct source** — don't guess who said what

## Handoff Protocol

At the end of every significant session:

1. Update `docs/active-threads.md` in the working repo
2. Write a handoff record to `docs/agent-log/handoffs/` using `templates/handoff-record.json`
3. Document any open escalations in `docs/escalations/`
4. Summarize decisions made and decisions pending

**Handoff record location:** `docs/agent-log/handoffs/[date]-[session-id].json`

**Handoff template:** `templates/handoff-record.json`

### Plugin Structure
```
WorldEngine/Plugins/NLTGovernanceSubsystem/
├── NLTGovernanceSubsystem.uplugin    ← Module descriptor (Name, Type, LoadingPhase, Plugins deps)
├── Source/NLTGovernanceSubsystem/
│   ├── NLTGovernanceSubsystem.Build.cs  ← Module rules (deps, include paths, lib linking)
│   ├── Public/
│   │   └── NLTGovernanceSubsystem.h    ← UNLTGovernanceSubsystem (UWorldSubsystem) + module interface
│   └── Private/
│       ├── NLTGovernanceSubsystem.cpp  ← Subsystem implementation (BlueprintCallable getters)
│       ├── AgentGovernanceState.h/.cpp ← FAgentGovernanceState struct
│       └── NLTGovernanceModule.cpp     ← IMPLEMENT_MODULE(FNLTGovernanceSubsystemModule, NLTGovernanceSubsystem)
└── ThirdParty/ASFDK → D:/nlt-repos/asfdk-cplus  (symlink)
```

### Build.cs Configuration
- **CppStandard:** Cpp23
- **PCHUsage:** UseExplicitOrSharedPCHs
- **PublicDependencyModuleNames:** Core, CoreUObject, Engine, LearningAgents, Json, JsonUtilities, GameplayTasks
- **PrivateDependencyModuleNames:** Projects, NavigationSystem, AIModule, MassEntity, MassCore, MassSignals, MassEngine, MassCommon, MassSimulation, Sockets, Networking
- **Include paths:** `ThirdParty/ASFDK/packages/{include,asfdk/include,toi/include,otoi/include,rrt-advocate/include,sleepwalker/include}`
- **Library:** `ThirdParty/ASFDK/lib/libasfdk.a` (pre-built static library)

### ASFDK-C++ Pillar Layout
```
asfdk-cplus/packages/
├── include/           ← Transitive deps (nlohmann/json, tl/expected, spdlog)
├── asfdk/             ← Umbrella header (ASFDK.h, ASFDK.cpp, GLIBC23Compat.cpp)
├── toi/               ← TermsOfInteraction pillar
├── otoi/              ← OTOIManager pillar
├── rrt-advocate/      ← RRTAdvocate pillar
└── sleepwalker/       ← SleepwalkerProtocol pillar
```

### Key Rules
1. **Never list individual .cpp/.h files in Build.cs** — UBT auto-discovers Source/*.cpp
2. **Module name must match exactly:** .uplugin "Name" == Source/ folder == Build.cs class == IMPLEMENT_MODULE second arg
3. **Build.cs requires `using System.IO;`** for Path/Directory helpers
4. **Target name is `WorldEngineEditor`** — using `WorldEditor` causes RulesError
5. **Symlink must be at plugin root** (`Plugins/NLTGovernanceSubsystem/ThirdParty/ASFDK`) — not inside Source/
6. **libasfdk.a must be built separately** before UBT build — see asfdk-cplus README
7. **Deep clean when changing plugin structure:** rm -rf Binaries/Intermediate/DerivedDataCache, regenerate project files

### Deep Clean Procedure
```bash
cd D:/nlt-repos/nlt-world-engine/WorldEngine
rm -rf Binaries Intermediate DerivedDataCache
rm -f WorldEngine.sln
# Then regenerate project files (see Build Commands above)
```

## Common Mistakes to Avoid

1. **Using `WorldEditor` instead of `WorldEngineEditor`** — causes RulesError
2. **Pushing directly to main** — always use a feature branch + PR
3. **Forgetting to update active-threads.md** — do it at session start AND end
4. **Writing handoff records with stale file lists** — verify `files_modified` matches actual diff
5. **Using wrong PR template** — always use `PULL_REQUEST_TEMPLATE/agent-contribution.md`
6. **Misattributing review comments** — Poolside AI, OpenCode, kilo-code-bot, CodeRabbit, and JDUB1216 all review PRs
7. **Placing ThirdParty symlink inside Source/** — must be at plugin root
8. **Missing `using System.IO;` in Build.cs** — causes CS0103 generation error
9. **Including LearningAgentsTraining in .uplugin** — plugin not installed in engine
10. **Skipping handoff records** — every significant session needs one
11. **Not escalating** — when in doubt, escalate. It's not failure; it's correct protocol.
12. **Forgetting to rebuild libasfdk.a** after ASFDK-C++ changes — stale .so will link old code
